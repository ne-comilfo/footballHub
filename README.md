# Football Hub ⚽

Футбольный портал: команды, игроки, матчи и статистика европейского футбола. Интерфейс на русском языке.

Проект начинался как витрина поверх чужих REST API, а сейчас работает на собственном бэкенде с PostgreSQL — внешние источники остались только там, где нужны живые данные.

## Возможности

- каталог команд и игроков с фильтрами, сортировкой и пагинацией на стороне сервера
- страницы команды и игрока: состав, статистика сезона, последние матчи
- матч дня, ближайшие игры и последние результаты в реальном времени
- топ бомбардиров по данным своей базы
- регистрация и вход, избранные команды и игроки
- тёмная и светлая темы, адаптивная вёрстка

## Архитектура

Монорепозиторий на pnpm workspaces из трёх пакетов:

```
client/              Next.js 16, App Router
server/              Express 5 + Prisma
packages/contracts/  общие zod-схемы и типы
```

Ключевое решение — **единый контракт**. Все доменные модели описаны zod-схемами в `packages/contracts`, типы выводятся из них через `z.infer`. Один и тот же файл импортируют клиент, сервер и скрипты импорта, поэтому тип и рантайм-проверка не могут разойтись: Express валидирует свой ответ перед отправкой, клиент — перед тем как положить в кеш.

Второе решение — **подменяемый источник данных**. Между приложением и данными стоит интерфейс `FootballDataProvider` с двумя реализациями: своя БД и внешние API. Переключается переменной окружения, компоненты об этом не знают.

```
компонент → hook → services/*Api.ts → /api/* → getProvider()
                                                  ├── own      → Express → PostgreSQL
                                                  └── external → TheSportsDB / API-Football
```

Сейчас работает гибрид: справочные данные из своей базы, живые матчи — напрямую из TheSportsDB, потому что счёт меняется по ходу игры и снимок в базе врал бы.

Слои на сервере разделены: `routes` описывают пути, `controllers` разбирают запрос и формируют ответ, `services` работают с Prisma и ничего не знают про HTTP. Между Prisma и сетью стоит маппер — `Decimal` и `Date` наружу не выходят.

## Стек

**Клиент** — React 19, Next.js 16 (App Router), TypeScript strict, TanStack Query v5, TailwindCSS v4 + shadcn/ui на `@base-ui/react`, react-hook-form, zod, next-themes.

**Сервер** — Node 22, Express 5, Prisma 7, PostgreSQL (Neon), jsonwebtoken, express-rate-limit.

**Инфраструктура** — pnpm workspaces, ESLint, Husky + lint-staged, GitHub Actions.

## Авторизация

Пара токенов: access — JWT на 15 минут, refresh — случайные 32 байта, в базе хранится только его хеш. Оба в httpOnly-куках, JavaScript их не видит.

Пароли хешируются scrypt из встроенного `node:crypto`, параметры записаны в саму строку хеша — при их изменении старые пароли продолжат проверяться по своим.

Refresh ротируется при каждом обмене. Если предъявлен уже использованный токен, он считается украденным и вся цепочка токенов пользователя гасится.

Обновление протухшего access-токена происходит в `middleware.ts` — клиентский код про это не знает, никаких интерцепторов и гонок при параллельных запросах.

## Запуск

Нужны Node 22, pnpm 10 и база PostgreSQL (подойдёт бесплатный проект на [Neon](https://neon.com)).

```bash
git clone https://github.com/ne-comilfo/footballHub.git
cd footballHub

cp client/.env.example client/.env.local
cp server/.env.example server/.env
# заполнить DATABASE_URL и одинаковый JWT_SECRET в обоих файлах

pnpm setup          # install + сборка контрактов + prisma generate
pnpm db:migrate     # создать таблицы
pnpm db:import      # наполнить справочник из TheSportsDB
pnpm dev
```

Клиент поднимется на `localhost:3000`, сервер на `localhost:5000`.

## Команды

| команда                                       | что делает                                                   |
| --------------------------------------------- | ------------------------------------------------------------ |
| `pnpm dev`                                    | клиент, сервер и watch-сборка контрактов                     |
| `pnpm setup`                                  | установка зависимостей, сборка контрактов, `prisma generate` |
| `pnpm db:migrate`                             | применить миграции и перегенерировать клиент Prisma          |
| `pnpm db:import`                              | наполнить базу из TheSportsDB                                |
| `pnpm db:sync`                                | подтянуть данные из API-Football порциями под дневную квоту  |
| `pnpm db:studio`                              | Prisma Studio                                                |
| `pnpm lint` / `pnpm typecheck` / `pnpm build` | проверки, те же что в CI                                     |

### Про `db:sync`

У API-Football на бесплатном тарифе около сотни запросов в сутки. Скрипт читает остаток прямо из заголовков ответа, берёт самые давно обновлявшиеся записи и останавливается, когда квота на исходе. Прерванный прогон продолжится со следующего запуска — состояние хранится в самой базе, в поле `apiSyncedAt`.

## Деплой

| часть  | где    | почему                                                |
| ------ | ------ | ----------------------------------------------------- |
| клиент | Vercel | родная площадка для Next.js                           |
| сервер | Render | нужен долгоживущий процесс, которого нет в serverless |
| база   | Neon   | PostgreSQL с бесплатным тарифом                       |

`JWT_SECRET` должен совпадать на обеих площадках — Next проверяет токен локально, чтобы не ходить в Express на каждый рендер.
